# Matrix Multiplication Benchmark: C++ CPU vs Classic CUDA vs Modern CUDA (Thrust)

A Google Colab laboratory comparing three implementations of dense square matrix multiplication, **C = A × B**, using double-precision (`double`) arithmetic.

The notebook generates C++/CUDA source files, compiles them, runs repeated benchmarks, and plots execution times and speedups relative to the sequential CPU implementation.

## Notebook

**File:** `matrix_multiplication_cpu_cuda_thrust_benchmark.ipynb`

Open [Google Colab](https://colab.research.google.com/drive/1GSLQl5FPKNOpFLezEekRgRUbqedS9dYt?usp=sharing), upload the notebook, then choose **Runtime → Change runtime type → GPU**. Run the cells in order.


## Implementations

| Implementation | Source generated by notebook | Approach |
|---|---|---|
| Sequential C++ CPU | `mm-cpu.cpp` | `std::for_each` over linear output indices, with a C++ lambda computing each dot product |
| Classic CUDA | `mm-cuda.cu` | Explicit `__global__` kernel, 2D grid and blocks; one thread computes one output element |
| Modern CUDA (Thrust) | `mm-thrust.cu` | `thrust::device_vector`, counting iterators, `thrust::transform`, and a device lambda |

All three implementations perform a straightforward **O(N³)** multiplication. They are educational baselines, not optimized tiled GEMM implementations or cuBLAS comparisons.

## Requirements

- Google Colab with an **NVIDIA GPU runtime**, or a local NVIDIA GPU with a compatible CUDA Toolkit
- `nvcc`, `g++` with C++17 support, and CUDA Thrust headers
- Python packages: `pandas` and `matplotlib`

In Colab, select **Runtime → Change runtime type → GPU**, then execute the notebook from top to bottom. The notebook checks `nvidia-smi`, `g++`, and `nvcc` versions.

## Notebook configuration

The configuration cell defines:

```python
SIZES = [512, 1024, 2048, 4096]
REPEATS = 3
BLOCK_SIZE = 64
TIMEOUT_SECONDS = 600
```

**Important:** The provided `BLOCK_SIZE = 64` creates a CUDA block of **64 × 64 = 4096 threads**, exceeding the maximum threads per block on typical NVIDIA GPUs (often 1024). **Change `BLOCK_SIZE` to `16` or `32` before running.** A `16 × 16` block uses 256 threads; `32 × 32` uses 1024 threads, if supported by the device.

`TIMEOUT_SECONDS` is defined in the notebook but is **not passed to `subprocess.run`** by the current `execute()` helper, so it does not currently enforce a timeout.

## Run the benchmark

1. Open `matrix_multiplication_cpu_cuda_thrust_benchmark(2).ipynb` in Google Colab.
2. Enable the GPU runtime and verify the CUDA compiler is available.
3. Set `BLOCK_SIZE = 16` (recommended starting point); optionally reduce `SIZES` for a quick test.
4. Run the source-generation cells, followed by the compilation cell.
5. Run the experimentation, summary, and plotting cells.

The notebook compiles the generated programs using:

```bash
g++ -O3 -std=c++17 mm-cpu.cpp -o mm-cpu
nvcc -O3 -std=c++17 mm-cuda.cu -o mm-cuda
nvcc -O3 -std=c++17 --extended-lambda mm-thrust.cu -o mm-thrust
```

You can also execute the binaries manually after compilation:

```bash
./mm-cpu 512
./mm-cuda 512 16
./mm-thrust 512
```

Each program prints the matrix dimension and measured elapsed time (seconds), separated by a tab.

## Timing methodology

- **CPU:** `std::chrono::steady_clock` measures the matrix multiplication function only; host matrix initialization is excluded.
- **Classic CUDA:** `std::chrono::steady_clock` measures device allocation, host-to-device copies, kernel execution, device-to-host copy, event handling, and cleanup. The code also measures kernel time using CUDA Events, **but does not print or export that measurement**.
- **Thrust:** `std::chrono::steady_clock` measures output-vector creation, device-vector allocations and transfers, the Thrust transform, copying the result to host, and device-vector cleanup. Host input initialization is excluded.

Each size/implementation pair gets one warm-up invocation followed by `REPEATS` measured executions. The summary reports the median and sample standard deviation of execution time.

**Interpretation caveat:** The GPU results include memory transfers and allocation overhead, whereas the CPU result measures multiplication alone. The comparison is therefore useful as an end-to-end GPU-vs-CPU exercise, but the timed regions are not identical. The notebook does not currently validate the numerical output matrices across implementations.

## Results and output files

After successful execution, the notebook produces:

| File | Description |
|---|---|
| `mm_benchmark_raw.csv` | Individual timings by matrix size, implementation, and repetition |
| `mm_benchmark_summary.csv` | Median execution time, standard deviation, and speedup |
| `mm_execution_time.png` | Execution-time curves with a logarithmic time axis |
| `mm_speedup.png` | GPU speedup curves relative to the sequential CPU baseline |

Speedup is computed as:

$$
\mathrm{Speedup}(N) = \frac{T_{\mathrm{CPU,median}}(N)}{T_{\mathrm{implementation,median}}(N)}
$$

A speedup greater than 1 means the implementation was faster than the CPU baseline for that matrix size; below 1 means slower.
